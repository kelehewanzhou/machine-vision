# 任务二：图像质量评分模块

## 1. 模块介绍

本模块负责项目中的图像质量评价任务，主要用于对输入图像进行多维度质量分析，并生成标准化的评分结果，为后续图像筛选和排序提供评分依据。

模块从图像的基础技术质量和整体美学表现出发，设计了五个评价维度：

- **清晰度（Sharpness）**：通过拉普拉斯算子计算图像清晰度，反映图像模糊程度。
- **曝光质量（Exposure）**：根据图像平均亮度以及过暗、过亮像素比例，评价曝光情况。
- **色彩表现（Color）**：通过图像HSV空间中的饱和度信息，评价色彩表现。
- **美学质量（Aesthetic）**：使用预训练NIMA模型对图像进行美学质量预测。
- **构图质量（Composition）**：结合主体覆盖率和显著性保留率，对图像构图进行评价。

各项指标经过标准化处理后，根据预设权重计算综合得分。当某一评价维度暂时无法获得有效结果时，模块会对其余有效维度的权重进行重新归一化，避免缺失指标直接影响综合评分的计算。

## 2. 文件结构

本模块涉及的主要文件如下：

```text
bdtfinal/
├── src/
│   └── score.py                 # 图像质量评分核心代码
│               
│
├── tests/
│   ├── score_testA_result.json        # 测试记录文件，记录每次测试的输入图像路径、输出评分结果等信息
│   └── test_score.py            # 评分模块单元测试及TestA测试
│
├── testA/                       # TestA测试数据集

│   ├── A02/
│   └── ...
├── config.json                   # 评分参数及权重配置
│
└── test_output/                 # 测试结果输出目录
    └── score_testA_result.json  # TestA批量评分结果
```

主要文件说明：

| 文件 | 作用 |
|---|---|
| `score.py` | 实现图像各维度评分、综合评分和结果封装 |
| `config.json` | 存放评分权重及相关参数配置 |
| `test_score.py` | 对评分函数进行单元测试，并使用TestA数据集验证批量评分功能 |
| `testA/` | 存放用于测试的图像数据 |
| `test_output/` | 保存批量评分生成的JSON结果 |

## 3. 环境与依赖

本模块基于Python开发，主要使用以下依赖：

- Python 3.13.5
- OpenCV
- NumPy
- PyTorch
- PyIQA
- Pillow
- pytest

其中，OpenCV和NumPy用于图像读取及基础质量指标计算；PyTorch和PyIQA用于加载和运行NIMA美学评价模型；pytest用于执行单元测试。

运行前需要安装相关依赖。可以在项目终端中执行：

```bash
pip install opencv-python numpy pillow pytest
pip install torch torchvision
pip install pyiqa==0.1.16
```

注意：PyTorch及其相关依赖应根据实际运行设备选择合适的安装版本。首次运行美学评价时，需要确保NIMA模型能够正常加载。

## 4. 运行方法

请先进入项目根目录：

```powershell
cd D:\bdtfinal
```

### 4.1 单元测试

执行以下命令：

```bash
python -m pytest tests/test_score.py -v
```

该测试主要检查评分模块各项基础功能是否能够正常运行，包括：

1. 清晰度评分函数；
2. 曝光评分函数；
3. 色彩评分函数；
4. 完整维度下的综合评分；
5. 缺失评价维度时的权重重新分配；
6. 所有评价维度均缺失时的异常处理；
7. NIMA模型加载失败时的处理；
8. 图像文件不存在时的处理；
9. 无效图像的异常处理；
10. 正常图像的评分流程。

### 4.2 TestA批量评分测试

在项目根目录下执行：

```bash
python tests/test_score.py
```

程序会自动读取`testA/`目录下的测试图像，对各个分组中的图片逐一进行质量评分。

TestA共包含A01—A20共20个图像分组。每组中的`GT.jpg`和数字命名的PNG等候选图片均参与评分，GT图片不会被排除。

程序运行结束后，会将评分结果统一保存至：

```text
test_output/score_testA_result.json
```

如果目录不存在，测试程序会创建相应的输出目录。

## 5. 输出结果说明

本模块最终以JSON格式保存批量评分结果，不额外生成CSV文件。

每条记录对应一张输入图像，主要包含以下内容：

| 字段 | 含义 |
|---|---|
| `group_id` | 图像所属分组 |
| `image_id` | 图像标识 |
| `raw_scores` | 各评价维度的原始评分指标 |
| `sharpness_score` | 清晰度标准化得分 |
| `exposure_score` | 曝光质量标准化得分 |
| `color_score` | 色彩表现标准化得分 |
| `aesthetic_score` | 美学质量标准化得分 |
| `composition_score` | 构图质量标准化得分 |
| `effective_weights` | 实际参与综合评分的各维度权重 |
| `total_score` | 图像综合得分 |
| `infer_time_s` | 图像评分耗时 |
| `status` | 本次评分的执行状态 |
| `errors` | 评分过程中记录的异常信息 |

其中，`total_score`为各有效评价维度按照实际权重计算得到的综合评分。`status`用于反映评分结果的完整程度，主要包括`ok`、`partial`和`error`。

## 7. 当前实现说明

目前，清晰度、曝光、色彩和美学四个维度已完成相应评分计算，并能够参与综合得分的生成。

构图质量评分需要依赖候选框生成模块提供的主体覆盖率和显著性保留率等信息。由于测试时尚未接入完整的上游数据，当前TestA测试中构图维度暂未参与综合评分，程序会根据有效维度重新分配权重，并将结果标记为`partial`。

后续接入候选框模块提供的相关数据后，即可进一步完成五个维度的综合评分。
